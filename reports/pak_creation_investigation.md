# PAK creation: investigation and recommendations

Scope: how Ironwail reads PAK files and what is inside them, compared with the supplied `pun.zip` release and the standalone
`pak0.pak`, and with this application's converter. Observed facts, hypotheses and decisions are kept apart.

* Ironwail source inspected: `ironwail-src/` (git `1eabd0df`, version 0.8.2 per `Quake/quakedef.h`). File/symbol references below are
  relative to `ironwail-src/Quake/`.
* `pun.zip` SHA-256 `d9da2059…55299c6`, 35,937,637 bytes. `pak0.pak` (standalone) SHA-256 `669df6c7…519f60b`, 93,563,955 bytes.
  Converter output for `pun.zip`: `bd31ff4a…4e6d7`, 112,019,344 bytes, 127 entries (unchanged by this pass).
* Per-path manifest: `reports/pun_manifest.json` (hashes and sizes only). Earlier summary: `reports/pun_reference_comparison.json`.

## 1. What Ironwail does (observed in source)

| Topic | Behaviour | Where |
|---|---|---|
| PAK directory | `PACK` header, 64-byte records (56-byte name, offset, length). More than 2048 entries is fatal; names copied with `q_strlcpy` into 56 bytes | `common.c` `COM_LoadPackFile` |
| Search order | game dir is pushed first, then `pak0`, `pak1`, … each onto the **front**, so `pakN … pak0`, then loose files. First `strcmp` match inside a PAK wins; lookup is case-sensitive | `common.c` `COM_AddGameDirectory`, `COM_FindFile` |
| Which maps the add-on menu lists | `maps/<name>.bsp` at top level only, `filelen > 32 KiB`; list name buffer is 32 bytes; start/end/dm/intro grouping is by name | `host_cmd.c` `ExtraMaps_Init`, `ExtraMaps_Categorize` |
| Map title / "playable" | worldspawn `message` read from the entity lump; BSP version must be 29, BSP2, 2PSB or Quake64 or the map is demoted to a bmodel | `gl_model.c` `Mod_LoadMapDescription`, `host_cmd.c` `ExtraMaps_ParseDescriptions` |
| Colored lighting | `maps/<name>.lit` accepted only if it starts `QLIT`, version 1, and size is exactly `8 + 3 × lighting-lump bytes`; otherwise a console message and white light. Ignored if it comes from a lower-priority game dir than the map | `gl_model.c` `Mod_LoadLighting` |
| Skybox | worldspawn `sky`, `skyname` or `qlsky` (one leading `_` stripped, last key wins); six faces `gfx/env/<name>{rt,bk,lf,ft,up,dn}` as png, tga, jpg, pcx or lmp. Zero faces: scrolling sky. Partial: "Couldn't load" per face | `gl_sky.c` `Sky_NewMap`, `Sky_LoadSkyBox`, `image.c` `Image_LoadImage` |
| Music | `music/trackNN.<ogg,opus,mp3,flac,wav,it,s3m,xm,mod,umx>`; the track number normally comes from the progs (`worldspawn.sounds`) | `bgmusic.c` `wanted_handlers`, `BGM_PlayCDtrack` |
| Game code | `progs.dat` must be version 6 and header CRC 5927 for the server VM, otherwise `Host_Error` when a map loads; foreign CRCs (CSQC, QuakeWorld, Hexen II …) are named in the message | `pr_edict.c` `PR_LoadProgs` |
| Startup script | `exec quake.rc` goes through the search path, so a mod's `quake.rc` replaces the base one | `common.c`, `host.c`, `cmd.c` `Cmd_Exec_f` |
| **Display name of an installed add-on** | `descript.ion` from the mod directory **on disk** (never from a PAK), then `mapdb.json` `episodes[].name` from the search path, then a built-in list. An episode whose `dir` is `copper` is ignored unless the gamedir is `copper` | `host_cmd.c` `Modlist_Add` |
| **Catalog entry** | `download`, `gamedir` required; `name`, `author`, `date`, `size`, `description.en` optional. The catalog `name` is used only if no local name exists | `host_cmd.c` `Modlist_RegisterAddons` |

Where metadata lives (not interchangeable):

* **A. Public catalog** (`content.json`): name, author, date, size, description. Generated by the app.
* **B. Inside the PAK**: only what the engine reads from the file system: `mapdb.json` (episode name only; `maps[]` entries are not
  read by Ironwail), `quake.rc`, maps, assets. `descript.ion` is *not* read from inside a PAK.
* **C. Application-only**: admin fields, the conversion record (new, `addons.conversion_report`).
* **D. Format**: the PAK carries no version, hash, comment or extra fields. Nothing can be "added to the PAK format".

## 2. `pun.zip` versus the standalone `pak0.pak` (observed)

127 effective entries in the converted ZIP (83 from the embedded `pak0.pak`, 44 loose, **0 overridden, 0 excluded, 0 rejected**) and 127 in the
standalone PAK. 74 paths are byte-identical, 37 share a path but differ, 16 exist only in the ZIP, 16 only in the reference.

| Group | Difference | Evidence | Read by Ironwail? | Implication |
|---|---|---|---|---|
| Maps (`start`, `pun1`-`pun5`: bsp, lit, map) | different builds: sizes differ, e.g. `pun3.bsp` 7,997,912 vs 6,932,860; `pun3` has 1504 vs 1506 entities | manifest, BSP entity lump | yes | different map versions; neither can be called "more correct" |
| `progs.dat` | 532,302 vs 542,854 bytes, both version 6 / CRC 5927 | header read | yes | different QuakeC builds, both engine-compatible |
| Sounds (18 paths differ, 6 reference-only) | e.g. `ambience/deep.wav` 401,112 vs 621,364 | manifest | yes | asset versions differ (the ZIP's `pun.txt` credits an extra ambient-sound pack) |
| Skyboxes | ZIP: `purplenebula_*` and `bal_swampn_*` tga (12 faces); reference: `pun_*` png (6 faces) | worldspawn `sky` values: ZIP maps name `purplenebula_`/`bal_swampn_`, reference maps all name `pun_` | yes | **each package is internally consistent with its own maps**; copying one set into the other would be wrong |
| Models | ZIP-only `misc_smoke`, `shalrath`, `v_axe`; reference-only `kelp`, `v_axe2` | manifest | yes (if used) | version differences |
| `quake.rc`, `mapdb.json` | reference only | read | yes | the ZIP release simply does not ship them; the converter must not invent them |
| `pun.txt` | ZIP only | read | no | documentation, kept |
| Music `track93-98.ogg` | in the ZIP loose (outside the embedded PAK) and in the reference; matches worldspawn `sounds` 93-98 | both | yes | present in both |

Two derived checks, both on the converted ZIP: every `.lit` is valid for its `.bsp`; every map that names a skybox has all six faces (`pun2` and `start` name none). Entity-referenced
files absent from the package: only `progs/player.mdl`, a base-game asset (same result for the reference).

`mapdb.json` in the reference gives "The Punishment Due" (identical to the ZIP's `pun.txt` title). That is corroboration, not a reason to
generate the file: the ZIP's author did not ship one.

**Hypothesis (not established):** the reference is a different build of the same episode (later or earlier is unknown) possibly repackaged for a
different distribution. Nothing in the data orders them in time.

## 4. Implemented

* `tools/pak_report.py` (new): read-only, bounded analysis (directory, 124-byte BSP headers, ≤64 KiB of each worldspawn, ≤256 KiB `mapdb.json`,
  ≤16 KiB text; 128 maps; 200 findings). No writes, no execution of anything from the package.
* `app.py`: additive `conversion_report` column (migration is idempotent); the record is stored with the package swap and replaced only if the
  replacement succeeds; detail page shows the inspection; `POST /addons/<id>/suggestion/<field>` applies one suggestion, recomputed from the
  stored package (the request carries no value), CSRF and login required, regenerates the catalog if published; upload message mentions the warning count.
* `templates/addon_detail.html`, `base.html`: findings (warnings first), suggestions with Apply, contents by type, maps table and conversion record
  in collapsible sections. All text is autoescaped. Also fixed the displayed package URL (`/public/addons/…` → `/addons/…`, the real route).
* **No change to generated PAK bytes** (see tests).

## 5. Requires approval before implementation

Items 9, 10, 11 (with a base-game file list) and any transformation of assets, `progs.dat`, maps, or generated startup scripts.

## 6. Remaining uncertainties

* No Ironwail runtime test of anything produced in this pass; this pass changes reporting only. (`qbj-acceptance.pak` was previously confirmed to load by the user.)
* The base-game soundtrack range (tracks 1-11) used to suppress `music.absent` is domain knowledge, not taken from the engine source.
* Readme parsing follows one common template (`Title :`, `Author :`, `Release date :`); other layouts yield no suggestion, never a guess.
* `music.absent` assumes the standard progs convention (`worldspawn.sounds` = CD track); a custom progs may differ. It is info only.
* The reference's relationship to the ZIP (newer, older, different distribution) is unknown.


## 7. Follow-up pass: background jobs, progress and opt-in conversion options

Engine facts established for this pass (source: `ironwail-src/Quake`, same commit):

* `image.c Image_LoadImage` tries `.png`, then `.tga`, then `.jpg` for an extension-less name and decodes with `stbi_load_from_file(..., req_comp = 4)`: always RGBA, one library for all three. A PNG with identical RGBA is therefore indistinguishable in game.
* The only place that treats `.tga` specially is `host_cmd.c SkyList_AddFile`, which feeds the console `sky <TAB>` completion; maps still load PNG skyboxes (`gl_sky.c Sky_LoadSkyBox`). Skyboxes are therefore a separate opt-in.
* `common.c` loads `localization/loc_<lang>.txt`, so `localization/` is a game directory (the classifier now knows it; `mapsrc/` is treated as an authoring folder).
* `gl_model.c Mod_LoadModel`/`Mod_LoadAliasModel`/`Mod_LoadSpriteModel`: a wrong model/sprite version is `Sys_Error` (fatal); `snd_wave.c WAV_ReadRIFFHeader`: unsupported WAV is skipped with a console message.

Implemented (all opt-in unless stated): background jobs with live progress and cancellation (removes the reverse-proxy timeout); upload progress bar; preview-before-build; root-folder selection; exclusion presets and custom patterns; lossless TGA→PNG; generated `mapdb.json`; keep source ZIP and rebuild; model/sprite/WAV header checks (always on, advisory); pending-uploads list; disk-space warning.

Evidence for the re-encoding claim (not just argument): a C harness built from Ironwail's own `stb_image.h` (`req_comp = 4`) decoded every TGA in `pun.zip` and `qbj_1.05.zip` and the PNG produced for it: 133 of 133 identical (405,616,645 B of TGA to 47,216,045 B of PNG, 12%); the application's own decoder also matched stb_image on all 133. Through the HTTP flow, `qbj` with every option: 121 of 121 converted images identical, 3 pre-existing PNGs byte-identical, 93 authoring files removed, package 1,608,206,950 → 1,165,481,366 bytes.

Not implemented: layered releases (a second ZIP applied over the first). It needs multi-source storage, UI and rebuild semantics and no evidence of need was found; recommend building it only on request.

Known limits: re-encoded output depends on the Pillow/zlib versions (recorded; identical on the host and in the container here); only 24/32-bit raw/RLE TGAs are converted; images over 16.7 megapixels are left alone.
